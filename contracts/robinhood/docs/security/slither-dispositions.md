# Slither dispositions

## How Slither runs

`bin/gate.sh` runs Slither only after the frozen identity, the build identity, the frozen release
surface, the compiled test listing and the executed test set are all green:

```
slither . --fail-medium --json ../slither.json --checklist
```

Slither's Foundry driver cannot follow this package's `libs = ["../stocks/lib"]` and `allow_paths`
outside the package root, so the gate first builds a self-contained copy of the package under
`reports/generated/slither-copy/` and runs the command above from that copy: the same `src/`, the
same compiler settings, the Base sources this package imports under `stocks-src/src/`, and the
exported dependency snapshot reached through relative symlinks under `lib/`. Every remapping is
rewritten by exact prefix, so the copy compiles the same bytes the frozen identity already proved
for the real package. Result locations below are relative to that copy: `src/...` is this
package, `stocks-src/src/...` is `contracts/stocks/src`, and `lib/...` is the dependency snapshot.

Slither drives the copy's own Foundry build, so the compiler and settings it analyzes under are the
frozen ones. That build is `forge build --build-info --skip ./test/** ./script/** --force`, so
tests and scripts are outside the analyzed scope. Everything the production sources import is
compiled into it, including the pinned dependency snapshot. Results whose source elements are all
dependencies are excluded because this package does not own those sources; a result that touches
both production code and a dependency remains visible.

`slither.config.json` disables nothing else. No detector is turned off, no severity is excluded,
and no triage database is used. Slither can be narrowed two entirely valid ways, a well-formed
configuration key or a well-formed command-line flag, so the gate pins both:

- **The configuration.** `slither.config.json` must equal one exact allowed shape:
  `exclude_dependencies` true, all six severity exclusions false, no path filter, and
  `compile_force_framework` foundry. An added key, a changed value, a path filter, or a detector
  exclusion list all fail, whether or not the key is spelled correctly.
- **The command line.** `bin/gate.sh` records the exact argv it is about to run and then runs
  that argv, and the gate compares the recording against the one allowed invocation. `--detect`,
  `--exclude`, `--exclude-low`, `--filter-paths` and `--triage-mode` are all rejected because none
  of them is in the allowed argv.
- **The detector portfolio.** The expected portfolio comes from the pinned Slither binary's own
  registered detector classes, read through the interpreter installed beside it, and the gate
  requires the analyzed run to report exactly that many detectors. `--list-detectors` is not the
  authority: it omits hidden detectors and under-reports the set that actually runs.
- `--fail-medium` fails the run on medium and high findings.
- Every result at **any** severity, including low, informational and optimization, gets its own
  row in the results table below. Each row is matched against an exact fingerprint, detector,
  impact, confidence and the copy-relative source mapping Slither reported, as a multiset in both
  directions. Two findings from the same detector at two locations are two fingerprints and need
  two rows; a row whose location is wrong or missing matches nothing and fails.
- The gate fails closed if a `*slither.db.json` triage database appears anywhere outside `out/`
  and the generated reports, so findings cannot be silently retired.
- The gate fails closed if Slither complains about its own configuration.
- The gate compares the number of contracts Slither says it analyzed against the number of
  contracts, libraries and interfaces declared under `src/` and `../stocks/src/`, so a narrowed
  source list cannot produce a quiet pass.
- Every inline `slither-disable` comment under `src/`, `test/` and `script/` needs a row in the
  inline suppressions table naming its detector, its rationale and a protecting test that Foundry
  lists; a suppression without a record, or one naming a test that does not exist, fails. The
  suppressions in `contracts/stocks/src` are recorded by that package's own dispositions.
