# Deployable size, code identity, hook callback cost, and complete-transaction gas

Every figure on this page is machine-reconciled. `bin/gate.sh` runs
`bin/check-requirements.py evidence` after the test run and fails if any published number differs
from the artifact or the executed measurement it came from, so nothing here is a figure a reader is
asked to take on trust.

## Deployable byte margins (`GAS-001`, `GAS-002`)

Generated by `bin/freeze-artifacts.py` from the compiler artifacts into
`reports/frozen/deployable-sizes.json`, re-checked byte for byte on every gate run, and reconciled
in Solidity against real deployed runtime lengths, real `EXTCODEHASH` values, and the exact ABI head
each constructor takes.

The last two rows are pinned dependency builds rather than Regent contracts. The ceremony deploys
`UERC20Factory` itself, and the Autolaunch factory constructor admits it by exact runtime code hash;
`UERC20` is the per-launch SUBJECT build that pinned factory CREATE2-deploys inside every launch
transaction, so no deployment packet ever encodes its constructor arguments. Both are recorded as
`n/a` in the two argument columns for that reason rather than as zero.

Every clone this graph creates is the fixed 44-byte Solady minimal proxy, derived from the prefix
and suffix literals in the production strategy's own clone-code-hash computation rather than
transcribed. `test_GAS_001_*` measures that length on a real clone the factory created, and compares
its `EXTCODEHASH` against the strategy's own `escrowCloneCodehash`.

The tightest margin in the set is the strategy's 5,589 runtime bytes, comfortably above the 1,000-byte
headroom the contract-worker rules require when no stricter budget is recorded, and none is.

### EVM code identity

Code identity is EVM-native: `runtime_keccak256` is what `EXTCODEHASH` returns for a deployed
instance whenever the artifact carries no immutable references, which is exactly the identity the
Autolaunch factory constructor admits its four dependencies by. Where a contract does carry
immutables, the artifact runtime still has those slots zeroed, so its keccak deliberately is *not* a
deployed codehash and the record says so. `test_GAS_001_*` proves that flag honest in both
directions. The SHA-256 recorded beside each hash is a packet-diffing digest only and is never an
admission identity.

The four `yes` rows are exactly the four identities `RegentsAutolaunchFactoryV1` refuses to be
constructed without, and `test_GAS_001_*` compares each frozen hash against both the production
constant and the deployed contract's own `EXTCODEHASH`.

A clone's own codehash is `keccak256(prefix ++ implementation ++ suffix)` over the 44-byte runtime,
so it exists the moment its implementation address does. The release manifest records that
derivation with a `deployment_pending` value rather than inventing one.

## Hook callback cost (`GAS-007`)

Measured as a controlled difference, not a swap total, and the control is exact. The hook charges
when the 1% lane floors above zero and returns immediately when it does not, so the lane boundary is
a single wei: a specified amount of `LANE_DIVISOR` charges a lane and `LANE_DIVISOR - 1` charges
nothing. The two swaps therefore run one wei apart, on pools the fixture opens identically — same
currency ordering, same fee, same tick spacing, same opening price, same liquidity, same direction,
same price limit, same router, same warmth — and the test asserts that sameness rather than assuming
it. Their difference is the callback and nothing else.

| Measurement | Gas |
| --- | ---: |
| controlled charging callback, cold (gas) | 204,313 |
| controlled charging callback, warm (gas) | 96,913 |
| production-lane callback, cold pool warm safe (gas) | 141,397 |
| production-lane callback, warm (gas) | 102,898 |
| pinned-router production swap, cold total (gas) | 246,562 |
| pinned-router production swap, warm total (gas) | 165,766 |
| second supported router, warm sync/settle swap total (gas) | 155,371 |
| pinned v4 target for a callback with external calls (gas) | 100,000 |
| pinned v4 hard ceiling for a callback with external calls (gas) | 300,000 |

### What each figure is

- **Controlled charging callback, cold — 204,313 gas.** The exact lane-boundary difference on a
  completely cold system: the first settlement anywhere pays the first touch of the Regent Safe, of
  the launch splitter, and of the splitter's onward destination.
- **Production-lane callback, cold pool warm safe — 141,397 gas.** A full one-REGENT swap on a third
  identically built pool, run after the boundary pair, so the Regent Safe and REGENT's own slots are
  already warm and only that pool's splitter is cold. This is the posture the second and every later
  launch on a live system meets on its own first swap.
- **The warm figures.** Controls only. They exist to prove the cold figures really were cold, and
  neither is the number a user pays on a pool's first swap.
- **Why both lane sizes.** At a one-wei lane the splitter's own floored 2% skim is zero and one ERC20
  push does not happen, so a boundary lane genuinely under-measures a production one. The test
  asserts that the warm production lane is the dearer of the two, which keeps the boundary figure
  from being read as the whole story.

### Disposition against the pinned v4 guidance

The applicable row is **callbacks with external calls** — this hook takes twice from the PoolManager,
approves, and calls the launch splitter, which itself moves value and may reach the live staking
contract. That row's target is 100,000 gas and its hard ceiling is 300,000 gas.

- **Cold, first settlement: 204,313 gas.** Above the target, comfortably inside the hard ceiling.
- **Cold, later launch: 141,397 gas.** Also above the target, also well inside the ceiling.
- **Warm: 96,913 / 102,898 gas.** Essentially at the target.

**Accepted.** Every figure is inside the pinned hard ceiling. The cold figures are the ones a real
user transaction meets, and they are the ones dispositioned; the warm ones are recorded as controls.
This is a nonblocking observation, not a defect.

For continuity with C4: that ticket observed 166,862 cold and 103,162 warm. The warm figures agree
with the production-lane warm figure here to within 0.3%. The cold figures differ because C4 measured
a swap total while this measures a lane-boundary differential that isolates the callback and includes
the cold Safe and splitter touches.

The second router settles the same swap for 155,371 gas, below the pinned router's 165,766 warm
total. The hook has no router allowlist and charges both identically.

## Complete-transaction gas (`GAS-003` through `GAS-006`) — not measured

These are fork claims and **no read-only Base provider was available to this candidate**, so no
complete-transaction figure exists. The measurement is written and mapped but unexecuted.

The shape it will take, recorded so the eventual figure can be checked rather than trusted:

- **The total is the applicable maximum, never a naive sum.** Post-Prague chains price calldata as a
  *floor* rather than a per-byte addition, so
  `total = max(intrinsic + calldata-bytes + execution, intrinsic + calldata-token-floor)`.
- **Gross of refund.** A refund is capped and cannot be relied on to bring a transaction back under a
  limit it exceeded, so refunds are deliberately not applied.
- **Cold, with a control.** Each envelope runs in a freshly created fork. `GAS-006` runs a second
  identical-shape launch in the same fork as a warm control and fails if it is not cheaper, which is
  what proves the cold figure was measured against genuinely cold external state. Cold is the user
  posture; warm is only the control.
- **Worst admitted conditions.** Maximum-length metadata in every field, the worst valid required
  raise, and — for the failure envelope — a partially bid auction rather than an unbid one, so the
  tick book, the refundable bidder inventory, and the unsold sweep are all at their largest.
- **The gas schedule comes from the header, not from this repository.** Intrinsic cost, per-byte
  calldata cost, and the calldata-token floor are read from `reports/frozen/fork-observations.json`
  for the exact header being measured, and the reviewed discovery pass is what puts them there.

Any complete envelope above 14,000,000 gas is a stop.
