Every clone this graph creates is the fixed 44-byte Solady minimal proxy, derived from the prefix
and suffix literals in the production strategy's own clone-code-hash computation rather than
transcribed. `test_GAS_001_*` measures that length on a real clone the factory created.

The tightest margin in the set is the strategy's 5,589 runtime bytes, comfortably above the 1,000-byte
headroom the contract-worker rules require when no stricter budget is recorded, and none is.

## 2. Hook callback cost (`GAS-007`)

Measured as a controlled difference, not a swap total. Two identical pools open cold side by side;
one takes a charging swap and the other takes a swap too small for either 1% lane to floor above
zero. Both do the same PoolManager work, so the difference is what the charging callback costs, with
the pool's own cold-storage cost cancelled out. The same pair is then repeated warm.

| Measurement | Gas |
| --- | ---: |
| charging callback, cold | 217,295 |
| charging callback, warm | 102,895 |
| pinned-router swap total, cold | 328,955 |
| pinned-router swap total, warm | 165,757 |
| second supported router, warm sync/settle swap total | 155,366 |

### Disposition against the pinned v4 guidance

The applicable row is **callbacks with external calls** — this hook takes twice from the PoolManager,
approves, and calls the launch splitter, which itself moves value and may reach the live staking
contract. That row's target is 100,000 gas and its hard ceiling is 300,000 gas.

- **Warm: 102,895 gas.** Essentially at the target, 2.9% over it.
- **Cold: 217,295 gas.** Above the target, comfortably inside the hard ceiling. The cold figure is
  dominated by first-touch costs at the Regent Safe, the splitter, and its onward destination —
  accounts every subsequent swap on that pool finds warm.

**Accepted.** Both figures are inside the pinned hard ceiling, and the steady-state cost a real
trader pays is the warm one. This is recorded as a nonblocking observation, not a defect.

For continuity with C4: that ticket observed 166,862 cold and 103,162 warm. The warm figures agree to
within 0.3%. The cold figures differ because C4 measured a swap total while this measures a
differential that isolates the callback and includes the cold splitter and Safe touches.

The second router settles the same swap for 155,366 gas, below the pinned router's 165,757. The hook
has no router allowlist and charges both identically.

## 3. Complete-transaction gas (`GAS-003` through `GAS-006`) — not measured

These are fork claims and **no read-only Base provider was available to this candidate**, so no
complete-transaction figure exists. The measurement is written and mapped but unexecuted.

The shape it will take, recorded so the eventual figure can be checked rather than trusted:

- **The total is the applicable maximum, never a naive sum.** Post-Prague chains price calldata as a
  *floor* rather than a per-byte addition, so
  `total = max(intrinsic + calldata-bytes + execution, intrinsic + calldata-token-floor)`.
- **Gross of refund.** A refund is capped and cannot be relied on to bring a transaction back under a
  limit it exceeded, so refunds are deliberately not applied.
- **Cold, with a control.** Each envelope runs in a freshly created fork. `GAS-006` runs a second
  identical-shape launch in the same fork as a warm control and fails if it is not cheaper, which is
  what proves the cold figure was measured against genuinely cold external state.
- **Worst admitted conditions.** Maximum-length metadata in every field, the worst valid required
  raise, and — for the failure envelope — a partially bid auction rather than an unbid one, so the
  tick book, the refundable bidder inventory, and the unsold sweep are all at their largest.
- **The gas schedule comes from the header, not from this repository.** Intrinsic cost, per-byte
  calldata cost, and the calldata-token floor are read from `reports/frozen/fork-observations.json`
  for the exact header being measured.

Any complete envelope above 14,000,000 gas is a stop.
