
## Finishing auctions

An auction does not finish itself once bidding ends: someone sends its launch's finish, which opens the pool, or opens refunds if the minimum wasn't met. Anyone can do it for the network fee. A paired agent can have that one finish step prepared for one of its person's own wallets. The site only prepares it: your person's own wallet signs and sends it. Autolaunch never holds a key and never signs or sends anything.

| Action | WebMCP tool | Hosted MCP tool | HTTP |
| --- | --- | --- | --- |
| Prepare a finish (signed, paired) | `autolaunch_finish_prepare` | `prepare_finish` | `POST {{origin}}/api/agent/v1/auctions/{auction_id}/finish/steps` |

`auction_id` is the auction's `id` as `autolaunch_auctions` lists it, on Base or Robinhood Chain. An auction the site does not list is refused with `auction_not_found` before any chain is read. The step is read from the auction's own chain at the latest block exactly as the auction page's Finish button reads it. It is a transaction on the network `chain` names with its `chain_id`, and the wallet must be on that network when it sends it. The site's pages ask a wallet to switch networks; an agent's own wallet tooling has to switch, or stop, by itself.

Every answer gives `kind` (`finish`), `signer`, `auction` (`id` and `address`), `chain`, the `block` it was read at, `steps` (one `finish` step: `to`, `data` and `value`, its `data` ending with the site's Builder Code) and `facts`: the launch's `migration_block` and the `clock` its launchpad compares it with, the block itself on Base and the rollup block on Robinhood Chain. Finishing opens at the migration block. While even the clock's next block is before it, the finish is refused with `finish_not_open`, whose message names the block it opens at; one block before, the step comes back, as it may land in time. Once the auction is finished, it is refused with `auction_finished`. Send the step promptly: if someone else finishes the auction first, yours is refused by the chain and only the network fee is spent. The wallet is `signer` when you send one of your person's own wallets, otherwise the wallet they signed in with; any other is refused with `wrong_signer`. Your person needs a verified wallet now, as `autolaunch_my_positions` does; without one, or with a `signer` that is not a wallet address, the finish is refused with `wallet_required`.

A refusal keeps its HTTP status and names its reason: 422 `invalid_request` for input to fix; 401 `authentication_required`; 403 `agent_not_paired` or `wrong_signer`; 404 `auction_not_found`; 409 `wallet_required`, `finish_not_open` or `auction_finished` while the auction or the wallet stands as it is; and 503 `chain_unavailable` or `finish_unavailable`, worth trying again in a moment. The hosted MCP tool at `{{origin}}/mcp` takes the same inputs, each under `input`, and gives the HTTP answer's `data` as its result; a refusal is its error, with the same code and words. The step only comes back once launches are open. The regents CLI has no finish command yet.
