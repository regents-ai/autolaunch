# Feature map

What a person or an agent can do on Autolaunch, and the automated check that proves it.
A check is a test (`file › test name`; ExUnit files under `platform/test/`, the TypeScript
one under `platform/assets/test/`, the CLI's under `cli/test/`) or a script. **Gap** means
nothing automated proves it today; it rests on manual review.

Map as of 27 October 2026. A release that adds or changes something here updates its line.

The agent journeys (`scripts/agent-journeys.sh`, specs in `platform/test/journeys/`) start a whole
local stack (a copy of Base with the version 3 contracts as deployed and open, the Robinhood lab, a local
Robinhood Chain with the Robinhood contracts and fixture stocks whose block clock the journeys move, a sign-in
service, this site and the regents command line) and play both sides: the regents binary is the agent, and Playwright at 390 with
touch and at 1280 is its person. Run them for any release touching pairing, agent routes, drafts or
launches.

## Wallet actions

Every wallet button goes through the same sender, proved by `onchain_steps.test.ts`: "hands
the wallet the exact reviewed bytes from the reviewed signer and reports the hash once", "two
presses in a row both reach the wallet while the first is still there", "sends through the
active wallet when it answers for another account, alone or in a batch", "sends nothing with no
active wallet, alone or in a batch", "reports a declined request and a step the review does not
have", and for batches "hands wallet_sendCalls exactly the reviewed calls, atomically, after the
chain read". A wallet off the step's network is asked to switch through Privy's own switch on
every press, for a Base or a Robinhood step, alone or in a batch, and once the switch resolves
the same press sends, naming the step's chain, with no read of the chain after it to refuse the
press; a declined switch is told apart from a failed one, sends nothing, and the next press asks again: "asks only when
the wallet is off the step's network, for a Base or Robinhood step sent alone or together",
"asks on every press off the step's network, and sends once the switch resolves", "sends
nothing when the switch is declined or fails, and the next press asks again and sends"; a
declined switch is counted and noted like any failed press:
`autolaunch_web/onchain_steps_rebuild_test.exs` "a declined network switch is a failed press
like the others: counted and noted"; every reason a press may be reported with has words beside
the buttons, whatever wallets the panel holds: "every reason a page may report has words, whatever
wallets the panel holds". Privy is given every network the site's steps go to, Base
first or none at all, and the page carries public doors only: `autolaunch_web/wallet_chains_test.exs`
(every case); Privy's own Base, viem's Robinhood Chain and a lab chain on the lab's own door:
`privy_chains.test.ts` (every case), which also gives Privy no network settings for a site
without a wallet chain. The real Privy bridge starting with these settings (the browser walk
stands in for it), Privy's own prompt as a wallet connects, and its switch in a real wallet app
(an extension, or a phone through WalletConnect): **gap**.

Accepted, not a fault (founder's ruling, 17 Nov 2026: the wallet swap does not happen, and it is
not guarded): the page never compares the wallet's account with the account a step was prepared
for. After the switch resolves, the step's chain rests on the chain id its request carries
(`chainId` on `eth_sendTransaction`, and on `wallet_sendCalls` for a batch). A step keeps the
address it was prepared for, as `from` and inside its call, so a press that a wallet signs from a
different active account pays from that account, while every call that names the prepared address
still names it, and the page shows that transaction as not the one it prepared. The calls that name
it: Earn's deposit credits it (`supply`'s `onBehalfOf`, `autolaunch/earn/steps.ex`) and Earn's
withdrawal pays it (`withdraw`'s `to`); Isolated Exposure's Buy and Sell pay it (the swap's
recipient, `autolaunch/exposure/steps.ex`); a Base bid in the auction's own currency is owned by
it (`submitBid`'s owner, `autolaunch/bid_actions.ex`). No other step's call names the prepared
address: it acts on a contract, a listing or a bid by its id, or on the sender itself, and a Base
launch names the treasury typed into its form.

## Points awards

Earning opens in production at 16 November 2026 17:00 UTC for every rule below (platform/config/prod.exs); everywhere else it is closed (no start time, no rule approved), so each check opens the rules for itself. A trade, a stake or a covered-call sale is offered to Points only when it is first saved, so one saved while its rule is not approved is never offered later; the one exception is a rebuild of a token's trades after the chain changed, which saves each trade again and offers it again then. A stake the chain later took back stays saved, and so does a covered-call sale the chain later dropped, which keeps what it earned (founder decision "5 a": the reader logs one warning and carries on). A rebuild asks the node again for the sender of every trade in the token's history, one lookup per transaction, four at a time, at most 40 transactions a pass, so a busy history is read over several passes.

## Hosted MCP and the Claude connector

An action only a person can do is a bug (founder rule, 28 October 2026). Which way in offers
each action an agent can take (a page's tool, hosted MCP at `/mcp`, the API, the Claude
connector and regents-cli) is the Agent access table in `/docs`, `/llms-full.txt` and
`/agents.md`, made from `platform/priv/capabilities.json` for the switches that are on
(`AutolaunchWeb.PublicDocuments`). A "No" there is a gap. On hosted MCP and the connector the
**Autolaunch MCP lane** closes it, as its operation becomes one action whose answer is the
browser tool's; in the CLI the **regents-cli lane** does, adding the command to
`cli/commands.json` when its switch goes on, so the CLI never offers what the site does not.

`POST /mcp` runs the tools `platform/priv/capabilities.json` marks hosted (its `hosted_tool`), each as its Ash action
under its policies (`AutolaunchWeb.Capabilities`, checked when it compiles; its `cli` column by
`autolaunch_web/capabilities_test.exs`). The connector's switch, `AUTOLAUNCH_CLAUDE_CONNECTOR_ENABLED`,
is off in production.
